# Research: 图像预处理最佳实践和库选择

**Feature**: 文本可编辑和OCR识别优化
**Date**: 2026-04-06
**Phase**: 0 - Research

## 图像预处理技术研究

### 图像歪斜校正

**问题分析**: 拍摄试卷/书本时，纸张不平导致图像歪斜，影响 OCR 识别

**解决方案**:

1. **Hough Transform (霍夫变换)**
    - 使用霍夫变换检测图像中的直线（文本行）
    - 计算直线角度，旋转图像使其水平
    - 适用于有明显文本行的文档
    - 实现：opencv.js 或手动实现简化版本

2. **投影法 (Projection Profile)**
    - 计算不同旋转角度下的水平投影
    - 选择具有最大投影峰值的旋转角度
    - 计算量小，适合实时处理
    - 对文档图像效果好

**决策**: 使用投影法进行歪斜校正
**理由**: 
- 计算量小，适合 Node.js 环境
- 对文档图像效果好
- 可以使用纯 JavaScript 实现或轻量级库

### 图像对比度和亮度调整

**问题分析**: 明暗不均匀的照片影响 OCR 识别

**解决方案**:

1. **直方图均衡化 (Histogram Equalization)**
    - 增强图像对比度
    - 适用于低对比度图像
    - 可能过度增强噪声

2. **CLAHE (限制对比度自适应直方图均衡化)**
    - 局部对比度增强
    - 避免全局直方图均衡化的过度增强
    - 更适合 OCR 预处理
    - 实现：opencv.js

3. **自适应阈值化 (Adaptive Thresholding)**
    - 根据局部区域调整阈值
    - 适用于光照不均匀的文档
    - 实现简单，纯 JavaScript 可实现

**决策**: 使用 CLAHE 进行对比度调整
**理由**: 
- 对光照不均匀文档效果最佳
- 避免过度增强噪声
- opencv.js 提供现成实现

### 图像锐化

**问题分析**: 模糊图像影响 OCR 识别

**解决方案**:

1. **Unsharp Mask (非锐化掩模)**
    - 从原图减去模糊版本
    - 增强边缘
    - 参数可调（强度、半径）
    - 实现：opencv.js 或纯 JavaScript

2. **拉普拉斯算子**
    - 边缘检测算子
    - 可以锐化图像
    - 实现：opencv.js

3. **高斯差分**
    - 减去两个高斯模糊版本（不同 sigma）
    - 保留高频信息（边缘）
    - 适合自然图像

**决策**: 使用 Unsharp Mask 进行锐化
**理由**: 
- 参数可调，适合不同模糊程度
- 可以控制锐化强度，避免过度锐化
- 纯 JavaScript 实现相对简单

### 图像降噪

**问题分析**: 噪点影响 OCR 识别

**解决方案**:

1. **中值滤波器**
    - 替换每个像素为中值
    - 有效去除椒盐噪声
    - 实现简单，纯 JavaScript

2. **高斯模糊**
    - 平滑图像，减少噪声
    - 可能导致图像模糊
    - 需要控制模糊程度

3. **双边滤波 (Bilateral Filter)**
    - 保留边缘的同时平滑图像
    - 适合 OCR 预处理
    - 实现：opencv.js

**决策**: 使用双边滤波进行降噪
**理由**: 
- 保留边缘信息，对 OCR 重要
- opencv.js 提供现成实现
- 效果优于简单的高斯模糊

## 图像处理库选择

### 候选库

1. **opencv.js**
    - OpenCV 的 JavaScript 绑定
    - 功能全面，性能良好
    - 支持所有需要的预处理算法
    - 下载大小：~10MB (主要 WASM)
    - 优势：功能全面，官方维护
    - 劣势：体积较大

2. **sharp**
    - 高性能 Node.js 图像处理库
    - 基于 libvips
    - 支持基本操作（调整大小、锐化、调整）
    - 不支持高级算法（歪斜校正、双边滤波）
    - 下载大小：~5MB
    - 优势：性能好，API 简单
    - 劣势：不支持高级算法

3. **jimp**
    - 纯 JavaScript 图像处理库
    - 无原生依赖，易于打包
    - 性能较低
    - 下载大小：~2MB
    - 优势：纯 JavaScript，易于打包
    - 劣势：性能低，功能有限

4. **自研轻量级预处理**
    - 针对 OCR 优化的简化算法
    - 纯 JavaScript 实现
    - 减小依赖
    - 下载大小：<100KB
    - 优势：离线打包友好，针对性优化
    - 劣势：需要开发和测试

**决策**: 使用 opencv.js
**理由**: 
- 功能全面，支持所有需要的预处理算法
- 性能良好，适合图像处理
- 官方维护，文档完善
- 可以通过 asarUnpack 配置正确打包
- 符合离线打包原则（作为 WASM 捆绑）

## 句子级别变更检测

### 技术方案

1. **句子分割服务扩展**
    - 现有 `server/services/sentenceSplit.js`
    - 扩展为可导入模块
    - 新增 `detectChanges(oldText, newText)` 方法
    - 返回：`{ changed: boolean, affectedSentences: [] }`

2. **句子哈希比较**
    - 对每个句子计算哈希值
    - 比较新旧哈希值检测变化
    - 快速、简单
    - 实现：Node.js crypto 模块

3. **简单文本比较**
    - 逐句比较文本内容
    - 忽略标点和空格差异（可选）
    - 简单、直观
    - 实现：纯 JavaScript

**决策**: 扩展现有句子分割服务，使用简单文本比较
**理由**: 
- 复用现有服务
- 简单文本比较足够检测句子变化
- 避免不必要的哈希计算
- 易于理解和维护

## OCR 结果质量评估

### 技术方案

1. **Tesseract 置信度分析**
    - tesseract.js 返回每个单词/字符的置信度
    - 计算平均置信度
    - 标记低置信度单词
    - 阈值：0-100，通常 <60 需要检查

2. **单词字典验证**
    - 将识别单词与英文词典对比
    - 统计非字典单词比例
    - 阈值：非字典单词 >20% 可能质量低

3. **文本长度和空行分析**
    - 检测异常短的行或空行过多
    - 可能表明识别问题
    - 阈值：空行 >30% 可能质量低

**决策**: 使用 Tesseract 置信度分析
**理由**: 
- 直接来自 OCR 引擎
- 准确反映识别质量
- 实现简单
- tesseract.js 已返回此信息
