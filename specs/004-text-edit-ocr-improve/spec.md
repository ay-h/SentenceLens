## User Scenarios & Testing *(mandatory)*

### User Story 1 - 文本内容可编辑 (Priority: P1)

用户可以自由编辑记录中的文本内容，修改OCR识别错误或调整文本。

**Why this priority**: 这是核心功能，直接影响用户对识别结果的修正能力，是使用体验的基础。

**Independent Test**: 用户上传图片后识别出文本，编辑其中错误的单词，保存后文本被更新且相关的翻译和分析被清除。

**Acceptance Scenarios**:

1. **Given** 用户已上传图片并完成OCR识别，**When** 用户点击编辑按钮进入编辑模式，**Then** 显示文本编辑器，允许用户修改任何文本内容
2. **Given** 用户正在编辑文本，**When** 用户修改了句子内容并保存，**Then** 句子的翻译和句子分析信息被清除
3. **Given** 整篇记录已翻译多句，**When** 用户只修改了其中一句的内容，**Then** 只有被修改句子的翻译被清除，其他句子的翻译保留
4. **Given** 用户正在编辑文本，**When** 用户修改后保存且句子发生变化，**Then** 文本被更新，相关翻译和分析被清除，系统提示重新翻译
5. **Given** 用户正在编辑文本，**When** 用户修改后保存但句子未变化（仅标点或空格），**Then** 文本被更新，翻译和分析保留

---

### User Story 2 - 智能重新翻译 (Priority: P1)

用户修改文本后，可以只重新翻译有变化的句子，而不是整篇重新翻译。

**Why this priority**: 提高效率，减少不必要的LLM调用，节省用户时间和API成本。

**Independent Test**: 用户修改了三句中的第二句，点击翻译按钮后只有第二句被重新翻译。

**Acceptance Scenarios**:

1. **Given** 记录中已有三句的翻译，**When** 用户修改了第二句的内容并点击翻译，**Then** 只有第二句被翻译，第一句和第三句的翻译保留
2. **Given** 记录中有多句翻译，**When** 用户修改多句内容并点击翻译，**Then** 只有被修改的句子被重新翻译，未修改的句子翻译保留
3. **Given** 记录中无翻译，**When** 用户修改文本后点击翻译，**Then** 整篇文本被翻译
4. **Given** 用户编辑了文本但未保存变化，**When** 用户点击翻译，**Then** 系统提示先保存文本更改

---

### User Story 3 - OCR图像预处理优化 (Priority: P2)

系统能够自动识别并处理图像质量问题，提高拍照文档的OCR识别准确率。

**Why this priority**: 直接影响用户体验，特别是拍照使用场景，能够显著减少手动修正的工作量。

**Independent Test**: 用户上传一张拍摄不理想的试卷照片，系统能够识别文字并准确率明显提高。

**Acceptance Scenarios**:

1. **Given** 用户上传了一张纸张不平的试卷照片，**When** 系统进行OCR识别，**Then** 图像被自动校正（去歪斜），文字识别准确率提升
2. **Given** 用户上传了一张明暗不均匀的照片，**When** 系统进行OCR识别，**Then** 图像被自动调整对比度和亮度，文字识别准确率提升
3. **Given** 用户上传了一张有模糊的照片，**When** 系统进行OCR识别，**Then** 图像被适当锐化处理，文字识别准确率率提升
4. **Given** 用户上传了一张有噪点的照片，**When** 系统进行OCR识别，**Then** 图像被降噪处理，文字识别准确率提升
5. **Given** 用户上传了一张清晰的照片，**When** 系统进行OCR识别，**Then** 跳过不必要预处理，直接进行识别，不增加处理时间
6. **Given** 用户上传了照片，**When** OCR识别过程中，**Then** 显示预处理进度（如"正在校正图像"、"正在调整对比度"等）

---

### User Story 4 - OCR结果质量评估 (Priority: P2)

系统能够评估OCR识别结果的质量，并在识别质量低时提示用户。

**Why this priority**: 帮助用户了解识别可靠性，及时进行手动修正，避免使用错误信息。

**Independent Test**: 用户上传一张低质量照片，系统识别后显示识别质量提示，用户及时进行修正。

**Acceptance Scenarios**:

1. **Given** OCR识别完成，**When** 识别质量低于阈值，**Then** 显示提示"识别可能不准确，请检查并修正文本"
2. **Given** OCR识别完成，**When** 识别质量较高，**Then** 不显示质量提示
3. **Given** OCR识别完成，**When** 识别过程中发现明显错误（如字符置信度低），**Then** 标记可疑单词供用户检查

---

### Edge Cases

- 用户编辑文本时删除了所有句子，系统如何处理？ **已澄清**：显示警告提示，要求用户确认是否删除所有内容（包括图片）
- OCR预处理时间过长（超过30秒）时如何处理？ **已澄清**：显示"处理时间较长，请稍候"提示，不中断处理，允许用户取消
- 图像预处理失败时如何回退？ **已澄清**：跳过失败的预处理步骤，使用预处理到当前步骤的图像继续 OCR
- 图片格式不支持时如何处理？ **已澄清**：显示友好错误提示，列出支持的格式，允许用户重新上传
- OCR识别返回返回空结果时如何处理？ **已澄清**：显示友好提示"未识别到文字，请检查图片内容或重新上传"，保留图片

- 多个用户同时处理同一记录时如何处理？ **已澄清**：采用最后写入策略，不进行并发控制
- 网络不稳定时翻译请求如何处理？ **已澄清**：显示网络错误提示，允许用户重试翻译


## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须允许用户编辑记录中的文本内容
- **FR-002**: 系统必须在文本编辑后检测句子是否发生变化
- **FR-003**: 系统必须在句子发生变化时清除该句子的翻译和句子分析信息
- **FR-004**: 系统必须在句子未发生变化时保留该句子的翻译和句子分析信息
- **FR-005**: 系统必须提供只翻译变化句子的功能
- **FR-006**: 系统必须能够识别图像中的歪斜并自动校正
- **FR-007**: 系统必须能够调整图像的对比度和亮度以优化识别
- **FR-008**: 系统必须能够对模糊图像进行适当锐化处理
- **FR-009**: 系统必须能够对有噪点的图像进行降噪处理
- **FR-010**: 系统必须对清晰图像跳过不必要的预处理步骤
- **FR-011**: 系统必须评估OCR识别结果的质量
- **FR-012**: 系统必须在识别质量低时向用户显示提示
- **FR-013**: 系统必须在预处理过程中向用户显示进度反馈
- **FR-014**: 系统必须在用户未保存文本更改时禁止翻译操作
- **FR-015**: 系统必须能够标记置信度低的OCR识别单词

### Key Entities *(include if feature involves data)*

- **句子变更状态**: 跟踪每个句子是否被修改、翻译是否清除
- **图像预处理配置**: 记录每种预处理算法的参数和阈值
- **OCR识别质量评估**: 记录每次识别的质量指标和可疑单词位置

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户编辑文本后系统能够正确检测句子变化，准确率达到100%
- **SC-002**: 智能重新翻译功能能够减少90%以上的不必要翻译请求
- **SC-003**: 图像预处理后，拍照文档的OCR识别准确率提升至少30%
- **SC-004**: 图像预处理处理时间不超过10秒（针对典型照片）
- **SC-005**: 用户能够在30秒内完成文本编辑和保存操作
- **SC-006**: OCR识别质量评估准确率不低于85%（即提示质量低的识别中至少85%确实需要修正）
- **SC-007**: 清晰图片的预处理跳过率达到100%

## Assumptions

- 用户主要在Windows平台上使用应用
- 用户拍摄的照片分辨率为1920x1080或更高
- 用户拍摄的文档主要为英文文本
- LLM翻译API调用有成本，减少不必要调用很重要
- 用户能够手动修正OCR识别错误
- 图像预处理使用客户端计算，不依赖外部服务
- 系统有能力检测文本句子级别的变化
- tesseract.js版本为v7，已集成到项目中
