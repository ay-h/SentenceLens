# Feature Specification: TextActions 工具栏与输入栏交互优化

**Feature Branch**: `002-textactions-layout`  
**Created**: 2026-04-01  
**Status**: Draft  
**Input**: User description: "修改 TextActions.tsx 的布局，按钮从左到右排列，把在最右边的删除按钮移到和其它按钮在一起，优化显示方案"

## 当前状态分析

`TextActions` 组件是一个水平工具栏，位于 `ImageThumbnails` 下方、`TextDisplay` 上方，包含以下元素：

1. **重命名**按钮（左侧）
2. **翻译文本**按钮（左侧）
3. **显示翻译**复选框（左侧，条件显示）
4. 弹性占位符 `flex-1`（中间撑开空间）
5. **删除**按钮（被推到最右侧，与其他按钮分离）

**问题**：删除按钮被 `flex-1` 撑到了最右边，与其他操作按钮在视觉上分离，不够紧凑，浪费空间。

此外，`BottomBar` 组件在用户选中句子后出现在页面底部，包含"取消"、"分析句子"、"删除分析"按钮。操作按钮远离用户视线焦点（句子本身），交互路径较长。

InputBar 使用固定高度的 textarea（`minHeight: 38px`, `maxHeight: 120px`），当用户输入多行文本时，输入框不会继续增高，仅依赖浏览器默认隐藏滚动条，导致内容可视区域有限且滚动体验欠佳。

**优化方向**：移除 BottomBar，将句子级操作（分析/取消/删除分析）内联到选中句子的附近位置；为 InputBar 文本输入框提供自动增高能力（基于内容行数），并设置明确的最大高度与滚动行为。

## Clarifications

### Session 2026-04-01

- Q: "分析句子"按钮的交互方式应该如何调整？ -> A: Option B — 移除 BottomBar，选中句子时在句子附近内联显示操作按钮（分析/取消/删除分析），使操作距离最短，用户视线不需要跳转到底部。
- Q: 内联操作按钮的具体显示位置？ -> A: Option A — 选中句子正下方显示一行紧凑的内联操作按钮。当有翻译文本时，操作按钮显示在翻译文本下方，避免遮挡翻译内容。需考虑翻译与操作按钮共存时的布局方案。
- Q: 内联操作按钮应该用什么样式？ -> A: Option B — 小型图标+短文字按钮，紧凑且可读，与现有按钮风格保持一致性。
- Q: 取消选择句子的交互方式？ -> A: Option C — 两种方式都支持：内联操作区有一个小"✕"按钮 + 再次点击已选中句子也可取消选中。
- Q: InputBar 文本框的最大高度与清空后的行为？ -> A: Option C — 最大高度 220px（约 7–8 行），达到最大高度时显示右侧垂直滚动条；文本发送后清空内容并恢复到默认高度。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 统一按钮排列（Priority: P1）

用户打开一条记录后，看到工具栏中所有操作按钮（重命名、翻译文本、删除）紧凑地从左到右排列在一起，无大段空白间隔。用户可以快速识别和点击任意操作。

**Why this priority**: 这是用户的核心需求——消除删除按钮与其他按钮的视觉分离，使工具栏布局更加紧凑直观。

**Independent Test**: 打开一条有内容的记录，目视确认所有按钮从左到右紧凑排列，删除按钮不再被推到最右侧。

**Acceptance Scenarios**:

1. **Given** 用户已选择一条记录, **When** 工具栏渲染, **Then** 重命名、翻译文本、删除按钮从左到右紧凑排列，之间无大段空白
2. **Given** 用户已选择一条记录且有翻译数据, **When** 工具栏渲染, **Then** "显示翻译"复选框紧跟在按钮组之后

---

### User Story 2 - 删除按钮视觉区分（Priority: P2）

虽然删除按钮移到其他按钮旁边，但用户仍能快速区分"危险操作"和"普通操作"。删除按钮通过颜色、间距或分隔符在视觉上与普通操作按钮有所区别，防止误触。

**Why this priority**: 将删除按钮移到一起后，需要防止用户误操作。视觉区分是安全性保障。

**Independent Test**: 打开记录，确认删除按钮虽然和其他按钮在一起排列，但通过颜色（红色边框/文字）以及适当的间距或视觉分隔，与普通按钮有明显区别。

**Acceptance Scenarios**:

1. **Given** 工具栏已渲染, **When** 用户浏览按钮, **Then** 删除按钮通过独特的颜色风格（红色调）与普通按钮视觉上可区分
2. **Given** 工具栏已渲染, **When** 删除按钮与其他按钮排列在一起, **Then** 删除按钮与相邻按钮之间有适当的额外间距或分隔线

---

### User Story 3 - 工具栏整体视觉优化（Priority: P2）

工具栏在视觉上更加精致：按钮组合紧凑，操作按钮与切换控件（显示翻译）之间有合理的视觉分组，整体工具栏高度和内边距适中，不会浪费垂直空间。

**Why this priority**: 这是整体 UI 打磨的增强项，在基本布局调整完成后进一步提升用户体验。

**Independent Test**: 整体审视工具栏在有/无翻译数据两种状态下的视觉效果，确认按钮紧凑、分组合理、无多余空白。

**Acceptance Scenarios**:

1. **Given** 工具栏已渲染（无翻译数据）, **When** 用户查看, **Then** 仅显示重命名、翻译文本、删除三个按钮，紧凑排列，工具栏不会因为缺少元素而显得空旷
2. **Given** 工具栏已渲染（有翻译数据）, **When** 用户查看, **Then** 操作按钮组和“显示翻译”切换控件之间有合理的视觉分组

---

### User Story 4 - 内联句子操作按钮（Priority: P1）

用户点击一个句子后，在该句子正下方立即出现一行紧凑的操作按钮（小型图标+短文字样式），包括“分析句子”、“删除分析”（已有分析时显示）和“✕”关闭按钮。不再需要视线跳转到页面底部的 BottomBar。

**Why this priority**: 这是核心交互优化——将句子级操作从远离视线的底部栏移到句子附近，大幅缩短操作路径。

**Independent Test**: 点击一个句子，确认操作按钮出现在句子正下方，点击“分析句子”可触发分析，页面底部不再有 BottomBar。

**Acceptance Scenarios**:

1. **Given** 用户点击一个未分析的句子, **When** 句子被选中, **Then** 句子正下方出现“分析句子”和“✕”按钮（无“删除分析”）
2. **Given** 用户点击一个已分析的句子, **When** 句子被选中, **Then** 句子正下方出现“分析句子”、“删除分析”和“✕”按钮
3. **Given** 显示翻译已开启且句子有翻译, **When** 用户选中该句子, **Then** 布局顺序为：句子 → 翻译文本 → 操作按钮，三者不重叠
4. **Given** 显示翻译已关闭, **When** 用户选中句子, **Then** 操作按钮直接出现在句子下方

---

### User Story 5 - 取消选择句子（Priority: P2）

用户可以通过两种方式取消选中句子：点击内联操作区的“✕”关闭按钮，或再次点击已选中的句子。两种方式覆盖不同用户习惯。

**Why this priority**: 取消选择是高频操作，需要多种快捷方式支持。

**Independent Test**: 选中一个句子后，分别通过“✕”按钮和再次点击句子两种方式取消选中，确认两种方式均可正常工作。

**Acceptance Scenarios**:

1. **Given** 用户已选中一个句子, **When** 点击内联操作区的“✕”按钮, **Then** 句子取消选中，内联操作按钮消失
2. **Given** 用户已选中一个句子, **When** 再次点击同一句子, **Then** 句子取消选中，内联操作按钮消失
3. **Given** 用户已选中句子 A, **When** 点击句子 B, **Then** 句子 A 取消选中，句子 B 被选中，操作按钮移到句子 B 下方

---

### User Story 6 - InputBar 自适应高度（Priority: P1）

用户粘贴或输入多行文本时，底部 InputBar 的文本框会根据内容自动增高，最多增至约 7–8 行（220px）。达到最大高度后，文本框右侧出现滚动条，用户可以滚动查看内容。清空或发送成功后，输入框恢复到默认高度，保障布局干净整洁。

**Why this priority**: 直接影响文本输入体验和空间利用，多行文本是常见场景。

**Independent Test**: 连续输入多行文本观察高度变化，确认在 220px 时出现滚动条；点击发送后输入框高度恢复默认值。

**Acceptance Scenarios**:

1. **Given** 用户输入文本不足 7 行, **When** 输入继续增加, **Then** 输入框高度随内容平滑增高，未出现滚动条
2. **Given** 用户输入文本超过 7–8 行, **When** 输入框达到最大高度 220px, **Then** 文本框右侧出现可用的垂直滚动条，内容可滚动查看
3. **Given** 用户点击发送并成功处理文本, **When** 输入框内容被清空, **Then** 输入框高度恢复至默认高度（38px 左右）

---

### Edge Cases

- 当没有 `currentRecord` 时，组件不渲染（已有 `if (!currentRecord) return null` 守卫，不受影响）
- 当翻译按钮处于加载状态（`translating`/`loading`）时，布局不应发生偏移或抖动
- 窗口宽度较窄时，按钮紧凑排列不会导致溢出或换行（如果发生溢出，应优雅地处理）
- 当“显示翻译”开启且选中句子时，内联操作按钮 MUST 出现在翻译文本下方，不遮挡翻译内容；布局顺序为：句子 → 翻译 → 操作按钮
- 当“显示翻译”关闭时，内联操作按钮直接出现在句子下方
- 分析过程中（analyzing 状态），内联按钮应显示加载状态且禁用点击，不应导致布局抖动
- 快速切换选中句子（从 A 切到 B）时，内联按钮应平滑转移到新句子下方
- InputBar 自动增高时 MUST 保持平滑动画，且在达到 220px 后显示滚动条；滚动条仅影响文本区域内容，不应撑开整体容器
- 当文本被清空（发送成功或手动删除）时，输入框高度 MUST 恢复默认值，避免残留的高占位

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 所有操作按钮（重命名、翻译文本、删除）MUST 从左到右紧凑排列，不使用弹性占位符将删除按钮推到右侧
- **FR-002**: 删除按钮 MUST 保留现有的红色/危险颜色风格，以便与普通操作按钮在视觉上区分
- **FR-003**: 删除按钮与相邻普通按钮之间 MUST 有适当的额外间距或视觉分隔（如分隔线），防止误操作
- **FR-004**: "显示翻译"复选框（条件显示）MUST 跟随在按钮组之后，保持合理间距
- **FR-005**: 工具栏布局 MUST 在翻译数据存在与不存在两种状态下均表现良好，无多余空白或布局抖动
- **FR-006**: 所有现有功能（重命名对话框、删除确认对话框、翻译操作、显示翻译切换）MUST 保持不变，仅调整视觉布局
- **FR-007**: 移除 BottomBar 组件，句子级操作（分析/删除分析/取消）MUST 以内联按钮形式显示在选中句子正下方
- **FR-008**: 内联操作按钮 MUST 使用小型图标+短文字样式，与现有按钮风格保持一致性
- **FR-009**: 当显示翻译开启且句子有翻译数据时，内联按钮 MUST 出现在翻译文本下方（句子 → 翻译 → 操作按钮），不得遮挡翻译内容
- **FR-010**: 用户 MUST 可通过两种方式取消选中：点击内联“✕”按钮，或再次点击已选中的句子
- **FR-011**: “删除分析”按钮 MUST 仅在句子已有分析结果时显示
- **FR-012**: Home 页面布局 MUST 移除对 BottomBar 组件的引用
- **FR-013**: InputBar 文本框 MUST 根据输入内容自动增高，最小高度约 38px，最大高度 220px
- **FR-014**: 达到最大高度时，InputBar 文本框右侧 MUST 显示可滚动的垂直滚动条，滚动范围仅限文本内容区域
- **FR-015**: 文本发送成功或手动清空后，InputBar 文本框 MUST 恢复到默认高度（最小高度）并移除滚动条

### Key Entities

- **TextActions 工具栏**: 位于主内容区顶部，承载记录级操作按钮和翻译切换控件
- **按钮组**: 重命名、翻译文本、删除三个操作按钮的集合
- **翻译切换控件**: “显示翻译”复选框，仅在有翻译数据时显示
- **内联句子操作区**: 选中句子正下方的一行操作按钮，包含分析句子、删除分析（条件）、✕关闭按钮
- **BottomBar（待移除）**: 原底部句子操作栏，将被内联句子操作区替代
- **InputBar 文本输入框**: 支持自动增高和滚动的多行文本输入区域，位于页面底部

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 删除按钮与其他操作按钮在同一区域从左到右排列，之间无大段空白
- **SC-002**: 用户可以在 1 秒内视觉区分删除按钮与普通操作按钮（颜色差异明显）
- **SC-003**: 工具栏在两种状态（有/无翻译数据）下均无布局抖动或多余空白
- **SC-004**: 所有现有交互功能（重命名、删除、翻译、显示翻译切换）100% 保持正常工作
- **SC-005**: 句子级操作（分析/删除分析/取消）均通过内联按钮完成，无需视线跳转到页面底部
- **SC-006**: 显示翻译时选中句子，翻译文本和内联按钮不重叠、不遮挡
- **SC-007**: 取消选择支持两种方式（“✕”按钮和再次点击句子），两种方式均可正常工作
- **SC-008**: InputBar 文本框在输入文本超过 7 行时高度限制在 220px，并显示垂直滚动条供滚动查看
- **SC-009**: 文本发送成功后，InputBar 文本框在 0.5 秒内恢复至默认高度，无残留滚动条或额外空白

## Assumptions

- 本次修改涉及 `TextActions.tsx` 布局调整、`BottomBar.tsx` 的移除/替换、`TextDisplay.tsx` 中新增内联操作按钮，以及 `InputBar.tsx` 的自适应高度调整
- 现有的设计变量（`--color-border`、`--color-danger`、`--color-text-secondary` 等）保持不变
- 不需要引入新的依赖或组件库
- 优化方案可包括：移除 `flex-1` 占位符、为删除按钮前添加分隔线或额外 margin、调整按钮间距、自适应 textarea 高度算法等纯 CSS/布局手段
